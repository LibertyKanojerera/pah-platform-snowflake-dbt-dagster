# ADR-015: Filtering CMS Part D to the PAH molecules

## Status

Accepted 2026-11-01.

## Context

The CMS Part D Prescribers by Provider and Drug dataset holds 28,023,892 rows
per release year. The project needs the subset prescribing four molecules:
treprostinil, selexipag, iloprost and epoprostenol. Server-side filtering is
mandatory rather than an optimisation.

Reconnaissance (see `docs/sources.md`) established three things that shape the
decision:

**`filter[Column]=Value` works and is exact-match.** Verified by contrast: the
unfiltered head of the table is Abrysvo and Boostrix Tdap, while
`filter[Brnd_Name]=Orenitram%20Er` returns Orenitram Er rows. No prefix,
substring or case-insensitive operator has been found. `keyword=` exists as a
broader search but its selectivity semantics are undocumented and unverified.

**The stored values are not the names anyone would guess.** The brand is
`Orenitram Er`, not `Orenitram`. The generic is `Treprostinil Diolamine`, not
`Treprostinil`. An exact-match filter on either guessed value returns zero
rows, and the pipeline then runs green while reporting that nobody in the
United States prescribes PAH therapy. This is ADR-002 recurring: in the
Databricks build, naive equality on brand name silently dropped roughly 450
Orenitram rows.

**Route is a property of the brand, not the molecule.** Treprostinil is
dispensed three ways: Remodulin subcutaneous or intravenous, Tyvaso inhaled,
Orenitram oral. The project's first research question is how prescribing
distributes across delivery routes by specialty, so collapsing to the molecule
destroys the variable being studied.

## Decision

**Filter server-side on `Gnrc_Name`, against a version-controlled vocabulary
of exact observed values, and derive route from `Brnd_Name`.**

Three parts.

**1. The filter predicate is generic name.** One request per distinct exact
`Gnrc_Name` value. Generic is the molecule-level concept, so a new brand
entering the market under an existing molecule is captured without a code
change. Brand-name filtering would require a new entry for every launch and
would miss anything not anticipated.

**2. The exact values live in a seed, not in code.** `drug_vocabulary.csv`
maps each observed exact `Gnrc_Name` to its molecule, and each observed exact
`Brnd_Name` to its route. The seed is the dbt seed introduced at plan S24 and
is the single place the vocabulary is stated. Nothing hardcodes a drug string
in Python.

**3. An unknown-value sweep guards the vocabulary.** Exact-match filtering
against a fixed list can only return what the list already knows, so a new
formulation would be omitted silently and the omission would look exactly like
a quiet quarter. Each extraction therefore runs a broad `keyword=` sweep on
the molecule stems ("treprostinil", "selexipag", "iloprost", "epoprostenol")
and compares the distinct `Gnrc_Name` and `Brnd_Name` values it sees against
the seed. Anything unrecognised is logged and raises, rather than being
silently included or silently dropped.

Route is then resolved from brand using the longest-prefix matcher carried
forward from ADR-002, which already handles the `Orenitram` versus
`Orenitram Er` class of mismatch.

## Rejected alternatives

**Filter on `Brnd_Name`.** Unambiguous and one request per brand, but requires
knowing every brand in advance and silently misses new entrants. The failure
mode is invisible, which is the disqualifying property.

**Use `keyword=` as the primary filter.** Fewer requests and tolerant of the
naming variations, but its matching semantics are undocumented. A filter whose
recall cannot be stated is not a filter you can write a data test against, and
the suppression and completeness tests at plan S36 depend on knowing exactly
what was requested.

**Hardcode the drug strings in `cms_part_d.py`.** Puts domain vocabulary in
code, where the analyst cannot see or change it and where dbt cannot test it.
The seed is reviewable in a pull request and joinable in SQL.

**Pull everything and filter client-side.** 28 million rows per year across
eleven years, to keep a few thousand. Not defensible on time, cost or courtesy
to a public API.

**Collapse brands to molecules at ingestion.** Would make filtering simpler
and destroy the route dimension, which is the dependent variable of research
question one.

## Consequences

**Request count scales with the vocabulary, not the data.** Roughly four to
eight requests per release year, plus the sweep. Trivial against an 11-year
backfill.

**The vocabulary is a maintained artifact.** It will drift from reality as CMS
publishes new formulations, and the sweep is what makes that drift loud. If
the sweep is ever disabled, the pipeline silently narrows — which is precisely
the failure described in ADR-010, so the sweep is not optional and its own
test must be able to fail.

**Two tests follow.** Plan S28 asserts the route matcher still resolves
`Orenitram Er` correctly, the regression test for ADR-002. Plan S36 asserts
the per-molecule row count sits inside an expected band, so a filter that
quietly stops matching fails the build rather than reporting zero.

**Selexipag's absence before 2016 is a true negative.** It was approved in
late 2015. The completeness test must not treat its absence from earlier
release years as a failure.
